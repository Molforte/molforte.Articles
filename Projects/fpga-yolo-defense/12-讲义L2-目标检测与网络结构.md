# [导师讲义·草稿] L2 目标检测与你的 YOLO-FastestV2 结构
> 内部备课稿：交付时按学员 L1 表现裁剪，节奏以对话为准。
> 素材锚点来源：SA1 简报（model_graph.py / decode_check.py / 模型配置_disaster_local.data）+ 导师已核对 main.c。

## 0. 本课目标
学员学完能脱稿讲：①什么是目标检测、YOLO 是什么思路；②自己的网络分几段、每段干什么；③79 层怎么数；④为什么这么小的模型够用。答辩问题族："为什么选它""网络结构""为什么 352""检测原理"。

## 1. 第一性原理：目标检测 vs 图像分类
- 分类：整张图"是什么"→ 输出 1 个标签。检测：图里有**几个**目标、**各在哪儿**→ 输出一组"框 + 类别 + 置信度"。
- 直觉类比：分类=问"屋里有人吗"；检测=问"屋里几个人、各站在哪、各自是谁"。
- 长延伸：检测是"感知"基础，下游是跟踪/识别/行为；竞赛报告的价值在于"端到端从模型到硬件"。

## 2. YOLO 的第一性思路："一刀切"的回归
- 关键洞见：**不先找候选区域（两阶段，如 R-CNN），而是把图像切成网格，让每个格子直接预测**"我这儿有没有目标中心 + 框多大 + 什么类"。一次前向出全部结果 → 实时。
- 你的网络落地（引导学员自己说）：352×352 图 → 最后留下两个"网格地图"：22×22（每格 16px，stride16）和 11×11（每格 32px）。格子越密越擅长小目标。
- 锚框（anchor）直觉：格子只告诉你"中心在这"，但目标有胖瘦大小——预置几个"典型框形"（如 (28,38)/(67,92)/(83,181)…），网络只预测"偏移量 + 缩放"，比直接回归宽高好收敛。main.c ANC 表 = 3 anchor × 2 尺度。

## 3. 逐段拆你的网络（对照 model_graph.py，边走边让学员复述）
```
输入 352×352×3
→ conv0 first_conv 3×3/s2 → 176×176×24 + ReLU
→ MaxPool 3×3/s2/p1        → 88×88×24
→ stage2 ×4 blocks(s=2 只在首块) → 44×44×48
→ stage3 ×8                 → 22×22×96
→ stage4 ×4                 → 11×11×192   ← "骨干"：特征越提越抽象、图越小、通道越多
→ LightFPN：S3(192@11) 1×1 降 72；上采样×2 与 S2 的 96 拼成 288 → 1×1 降 72
→ head(cls/reg 两支，5×5DW+1×1 轻量卷积)
→ 输出每格 21 通道 = reg12 + obj3 + cls6   (3 anchors 共享 cls)
```
- ShuffleV2Block 要讲清（学员最大盲区之一）：shuffle 把通道"洗牌拆两半"，一半走 main(pw1×1→dw3×3→pw1×1)，另一半捷径 concat——**不升通道**，省算力。s=2 时另一支走 proj（也含 dw+pw）负责降分辨率。
- 为什么叫"Fastest"：全网络只有 **0.23M 参数**（YOLOv3-Tiny 8.7M 的 ~1/38），INT8≈250KB，嵌入式能塞。
- 79 层怎么数（直接演示命名规律）：conv0..conv72 = 73 个 + out_reg/obj/cls ×2 尺度 = 6 个 → **79**。命名 backbone_{stage}_{块}_branch_{main|proj}_conv{N}；池化/上采样/拼接/洗牌不占编号，只在执行序里。

## 4. 答辩表述（让学员组织，导师补）
示例骨架："我选用 YOLO-FastestV2 作为算法原型，因为灾后救援要上板实时，模型必须轻——它只有 0.23M 参数、INT8 后约 250KB。网络分三部分：轻量骨干（ShuffleNetV2 式）逐级提取特征，LightFPN 把深层语义和高分辨率浅层融合，双尺度检测头输出目标框。针对救援场景用自采/公开火灾烟雾数据训练，6 类目标，AP 66%。"

## 5. 追问防御（预埋答案点）
- 为什么不是 YOLOv5/v8？→ 板载存储与时延约束，0.23M 是硬指标；v8 在 CPU 上更慢（可对比）。
- 为什么 352？→ 训练配置如此；分辨率每降一半计算量降 4 倍，是速度/精度折中。
- 为什么只两尺度、没有更浅的 44×44 大尺度？→ 轻量化取舍；小目标（远处火点）是本方案已知弱点——诚实回答可加分。
- "检测头为什么 5×5 DW？"→ 扩大感受野又不加参数量（DW 每通道一个核）。

## 6. 长期延伸
- 检测演进：anchor-based(YOLOv2+) → anchor-free(FCOS/YOLOX) → query-based(DETR)；NMS 正在被端到端取代。
- 你的"骨干+FPN+Head"结构是所有现代检测器共享的骨架——学通一次，换模型只是换零件。
- 板上部署的永恒权衡：模型越小越快越省片内存储，但精度越低——答辩"为什么这么设计"都要回到这个权衡。
