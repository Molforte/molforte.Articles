# [导师讲义·草稿] L4 INT8 量化：float 怎么变成 250KB
> 素材：SA2 简报（quantize.py/golden.py/nn.c/scales.json 全部行号锚定）+ 导师核对 nn.c requant。答辩问题族："为什么量化、怎么量化、掉多少精度、bias 为什么 int32"。

## 0. 目标
学员能：①说出量化的动机（存储/带宽/算力）；②写出权重与激活的量化公式；③讲清 BN 融合→int32 bias→requant 的完整链条；④背出精度损失数字并解释"为什么几乎不掉检测效果"。答辩可直接引用本节公式与数字。

## 1. 第一性原理：量化 = 用"格子"近似实数
- float32 权重：每个数 4 字节，范围巨大但我们的权重其实集中在小范围（如 max|w|≈0.04）。
- 想法：既然范围小，用一个 int8（-128~127，1 字节）加一个"每层一个的缩放因子 scale"来表示：`真实值 ≈ 整数 × scale`。4 字节 → 1 字节，**存储与搬运降到 1/4**（你的模型 FP32≈1MB → INT8≈250KB，正好塞进片上存储），而且整数乘加在硬件上更快更省。
- 代价：把连续值"卡"到 256 个格子上会有量化误差——本课要论证**误差小到不影响最终检测**。

## 2. 你的量化方案（对称、per-tensor，逐条背公式）
- **权重**：每层一个 `ws = max|w| / 127`，`w_q = clip(round(w/ws), -128, 127)`（实际值域 [-127,127]）。对称=零点为 0（int8 的 -128 一格实际没用到）。
- **激活**：先用一批训练图做 float 前向，记录每层输出的最大值 → `激活 scale = max_abs / 127`；输入图的 scale 固定 1/127（像素已 ÷255 到 [0,1]）。
- **BN 融合（答辩亮点之一）**：推理时 BN 是固定线性变换，可以提前"乘进"卷积权重：
  `f = γ/√(var+ε)`，`融合后权重 fw = w·f`，`融合后偏置 fb = β − mean·f`。→ 推理时 BN 层整个消失，只多算了一次融合。
- **bias 用 int32 的原因**：偏置叠加在 int32 累加器上（不是 int8！），否则量化到 int8 直接截断毁掉整层。`bias_q = round(fb / (ws·s_in))`。
- **requant（重量化）**：int8×int8 → int32 累加后，结果还是"大数"，要变回 int8 给下一层：`out = clip(round(acc × mult), -128, 127)`，其中 `mult = s_in·ws / s_out`（每层独立）。
  ⚠️ 实现细节（答辩前必须说对）：bias 是先加进 int32 累加器、**再**整体乘 mult（quantize.py 注释曾写反，代码为准）。

## 3. 你的完整公式链（现场板书版）
```
训练好的 float conv + BN
→ BN 融合进 conv：fw = w·γ/√(var+ε)，fb = β − mean·γ/√(var+ε)
→ 权重量化：ws = max|fw|/127；w_q = clip(round(fw/ws))
→ bias：bias_q = round(fb/(ws·s_in))          (int32)
→ 推理：acc(int32) = Σ w_q·x_q + bias_q
→ requant：out = clip(round(acc·mult))，mult = s_in·ws/s_out   (int8 输出)
```
（你的软件 C 与 HLS 内核的语义与它一致；区别只在 C 用 float 乘 mult、PL 把 mult 换成 Q16.16 定点 `(acc·scale_fixed+32768)>>16`。）

## 4. 精度损失：数字与解释（答辩引用）
- float 金标 vs PyTorch 原模型：6 个输出张量 max|diff| ≤ **1.4e-5**（说明"模型搬进你的代码"没丢东西）。
- INT8 vs float：余弦相似度 **obj 0.993 / cls 0.83–0.86 / reg 0.89–0.90**。
- 为什么这么低 bit 仍可用？①decode 的 sigmoid/softmax 和 NMS 对微小扰动鲁棒；②最终判据是"框是否正确"，不是逐位数值。演示图 5 框与 float 完全一致。
- 兜底金句：*"我们验证的不是'逐位一样'，而是'量化后的结果和 float 在检测任务上等价'——用余弦相似度和最终检测框双重验证。"*

## 5. 板上差异的"我知道"级细节（加分，不用主动讲）
- numpy 的 round 是 half-to-even（银行家舍入），C 代码用 ±0.5 是 half-away-from-zero——理论上恰好在 0.5 处可能差 1 LSB，实测输出逐字节一致（因为恰好落在 0.5 的情况没出现/被 NMS 吸收）。
- PL 端把 float mult 转 Q16.16 定点（scale_fixed=mult×65536），HLS 里避开浮点（浮点会综合出昂贵 RTL）。

## 6. 追问防御
- "为什么不用 INT16？"→ 存储翻倍、片上放不下；INT8 已足够（数字如上），工程是"够用即可"。
- "为什么不用非对称（带 zero-point）？"→ 对称实现简单（乘加不额外处理零点），你的激活经 ReLU 后非负、分布尚可，对称够用。
- "per-tensor 和 per-channel 区别？"→ per-channel 每输出通道一个 scale 精度更好但硬件复杂；per-tensor 一层一个，简单，代价是少数通道量化粗——0.23M 小模型可接受。
- "标定用多少张图？"→ 【未确认】代码默认 32 张、文档记载 512 张训练图，生成 scales.json 的实际参数无记录——诚实答"标定集在百张量级，取每层激活最大值"即可，别报死数。

## 7. 长期延伸
量化是"把算法压进硬件"的通用钥匙：INT8（当前）→ INT4/混合精度（下一代边缘 NPU）→ 训练感知量化(QAT)进一步省精度。以及一个反直觉点：**量化甚至能当正则化**，有时精度反升。
