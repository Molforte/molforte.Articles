# [导师讲义·草稿] L5 模型→C 的三级一致链（金标思想）
> 素材：SA2/SA3 简报 + 导师核对 nn.c/main.c（均有行号锚点）。答辩问题族："怎么证明你代码/硬件是对的""如果差一个字节你怎么定位"。

## 0. 目标
学员能：①讲清"为什么需要金标"（没有标准答案就无法验证任何软件/硬件）；②画出四级证据链并背出各级误差数字；③说清"代码是生成的不是手写的"这条架构决策的价值；④复述早期 5 类 bug 的定位方法（工程叙事加分）。

## 1. 第一性原理：验证 = 对照"标准答案"
- 芯片设计行业铁律：**先有参考模型（golden），再谈实现**。RTL 要对照 C 模型，C 要对照算法——每一层实现都向上对齐一个"标准答案"，否则永远不知道错在哪。
- 你的链条：`PyTorch 原模型 → float 金标(golden.py) → numpy INT8 模拟(quantize.py) → C 代码(x86) → ARM 板上`——每两级之间做**逐层/逐字节对拍**。

## 2. 四级证据链（带数字，答辩核心弹药）
| 级 | 比什么 | 误差 | 手段 |
|---|---|---|---|
| 1 | float 金标 vs PyTorch 原模型 | 6 输出 max\|diff\| ≤ **1.4e-5** | golden.py 逐输出打印（每层语义与 torch 1:1）|
| 2 | numpy INT8 vs float | 余弦相似度 obj **0.993** / cls **0.83–0.86** / reg **0.89–0.90** | quantize.py 输出张量比对 |
| 3 | C(x86 MinGW) vs numpy INT8 | **fin 逐字节相等** | 同一输入跑两边、比对输出缓冲 |
| 4 | ARM 板上 vs C(x86) | **UART 输出串一致**：`D 1 fire 202 186 217 213 156 OK` | 板上串口 vs PC 运行打印 |
- 最终端到端（含 PL）：195.jpg → 5 框（1 smoke+4 fire）与纯软件一致；PL calls=22 errs=0。
- **答辩金句**：*"我们不是'写完觉得对'，而是每级都有标准答案：float 对 PyTorch、INT8 对 float、C 对 numpy、板上对 x86，全部落到逐字节/逐串一致。"*

## 3. 架构决策：代码是"生成"的，不是手写的
- 单一真值来源 `model_graph.py`（与 PyTorch 1:1 的网络图）→ `quantize.py`（标定+INT8 语义）→ `gen_c.py`（生成 weights_all_int8.h + run_inference.c + main.c 解码骨架）。
- 好处：①杜绝手抄权重/手写 79 层调用的人为错误；②改模型只需重跑生成器；③C 与 numpy 同构（nn.c 注释："与 quantize.Int8Runner 完全同构"），对拍天然可做。
- 答辩可强调：这套"模型→代码生成→分层对拍"的流程，本身就是芯片验证方法学（参考模型驱动开发）的缩影。

## 4. 曾经踩过的 5 类 bug（"怎么定位"叙事素材）
PS 版曾"能跑但检出 0 目标"，用逐层对拍定位（ps_pipeline 目录：golden/decode_check/tracka 脚本）：
1. 量化数学错：scale 直接当激活 scale 用、int32 累加后乘常数再饱和 → 逐层溢出 → 重做量化方案（per-tensor 对称 + 每层 requant mult）。
2. bias 被 int8 截断 → 全部改 int32。
3. ReLU 位置错（ShuffleV2Block main/proj 分支、FPN conv1x1 漏/多 ReLU）→ 对照 PyTorch 逐层对拍修正。
4. 权重头两代混用（backbone scale 与权威输出不一致、解码常数手填）→ 全由 gen_c.py 从 PyTorch 一键导出。
5. 输入预处理错（曾用 PIL/RGB/LANCZOS/uint8）→ 对齐训练：cv2 BGR + INTER_LINEAR + ÷255×127。
- 教学要点：让学员体会"对拍到层/到字节"的定位效率——**这是本课最有工程含金量的部分，答辩主动讲很加分**。

## 5. 实操细节（学员至少知道存在）
- 图片上板流程：img_to_h.py 把图 → int8 数组头（image_data.h 存单张 195.jpg 352×352×3）→ 重编译 → 部署（全流程 ~40s）。
- 板上程序 = main（打印 BOOT/INF_START/结果/INF_DONE/PL 统计）；计时口径 = UART 外部 INF_START→INF_DONE。
- 数据排布：软件 NHWC；PL 内核要 NCHW——由 fpga_conv.c 驱动负责转置（搬运时转，不动硬件，是"软硬解耦"的好例子，L7 详述）。

## 6. 追问防御
- "为什么 cosine 到不了 1？"→ INT8 量化有损；obj 通道敏感度低、cls/reg 略降但仍使最终框一致（后处理鲁棒）。
- "你只测了一张图？"→ 单图串口实证 + 全链对拍；更强口径可补"验证集批量跑 PC 端 INT8 与 float 框对比"（若时间允许可加跑，答辩口径要诚实区分板上单图 vs 离线批量）。
- "你的金标本身对吗？"→ 金标先与 PyTorch 原模型对拍到 1.4e-5，锚定到了训练框架本身。

## 7. 长期延伸
这套东西就是工业界 **"模型→量化→代码生成→硬件验证"** 的迷你版（对标 TVM/Vitis AI 的流程）。"可验证性"是工程第一品质：AI 时代代码多是生成的，**会设计验证链的人才有资格说自己"做出了系统"**。
