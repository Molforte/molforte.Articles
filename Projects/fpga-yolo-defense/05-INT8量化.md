# L4 INT8 量化 · 组员共享版
> 用途：答辩谈到"为什么量化、怎么量化、掉多少精度、250KB 从哪来"时用。本课是全项目"为什么模型能塞进 FPGA"的答案。

## 1. 量化三动机（答辩必答）
① **存储**：float32 一个数 4 字节 → int8 1 字节，**省 4 倍**（模型约 1MB → 约 250KB，片上放得下）；② **带宽/速度**：数据搬运量减 1/4，推理更快；③ **能耗/资源**：整数乘加比浮点省电省资源，硬件不需要浮点单元。

## 2. 你的量化方案（对称、每层一个 scale）
**量化 = 用 256 个整数格子 + 一个缩放因子近似实数**：真实值 ≈ 整数 × scale。
公式链（答辩板书）：
```
① ws = max|w| / 127                      （权重 scale，每层一个）
   w_q = clip(round(w / ws), -128, 127)
② BN 融合：f = γ / √(var + ε)            （推理时 BN 消失）
   fw = w·f ；fb = β − mean·f
③ bias_q = round(fb / (ws · s_in))       （int32！）
④ 推理：acc(int32) = Σ w_q·x_q + bias_q
⑤ requant：out = clip(round(acc × mult))，mult = s_in·ws / s_out
```
逐个说人话：
- **ws**：把该层最大权重映射到 127，其余等比例缩放；**对称** = 零点为 0，实现最简单。
- **BN 融合**：推理时 BN 是固定线性变换（γ 缩放 + β 平移），提前乘进卷积权重 → 少一层运算。
- **bias 为什么 int32**：bias 加在 int32 累加器上，量级与累加和同阶；若也压成 int8 会被直接截断、毁掉整层。
- **requant**：int8×int8 累加会涨到 int32，乘一个小数 mult 缩回 int8 交给下一层（软件用浮点乘；PL 上为避免浮点硬件，把 mult 转成 Q16.16 定点：`(acc×scale+32768)>>16`）。

## 3. 精度数字（背）
| 对比 | 结果 |
|---|---|
| float 金标 vs PyTorch 原模型 | max\|diff\| ≤ **1.4e-5**（搬进代码没丢东西）|
| INT8 vs float | 余弦相似度：obj **0.993** / cls 0.83–0.86 / reg 0.89–0.90 |
- 为什么掉精度但框还一致：decode 的 sigmoid/softmax/NMS 对微小扰动鲁棒；验证目标是"检测任务等价"，不是逐位相等。实测演示图 5 框与 float 完全一致。
- 答辩金句：*"量化前后余弦相似度 obj 0.99+；到检测任务上框与 float 一致——量化误差没有转化为检测误差。"*

## 4. 问答与口径
- "为什么不用 INT16？"→ 存储翻倍、片上放不下；INT8 数字已证明够用。
- "per-tensor vs per-channel？"→ 每层一个 scale（per-tensor）实现简单；per-channel 每输出通道一个 scale 更准但硬件复杂，0.23M 小模型没必要。
- ❌ "存储省 8 倍" → ✅ **4 倍**。
- ❌ "requant 是移位" → ✅ 软件是浮点乘（`acc×mult`）；移位是 PL 端 Q16.16 的实现。
- ❌ "bias 在 requant 后加" → ✅ bias 先加进 int32 acc，再整体乘 mult。
- 舍入细节（被深挖再亮）：numpy 是"银行家舍入"，C 代码 ±0.5 远离零舍入——理论上恰在 0.5 处可差 1，实测输出逐字节一致。

## 5. 答辩 30 秒表述
> "模型原始权重是 float32，约 1MB，塞不进片上存储。我做对称的每层单 scale 量化：权重压成 int8、约 250KB，同时把 BN 融合进卷积、bias 保持 int32、每层做 requant。量化后和 float 的余弦相似度在 0.83–0.99，最终检测框与 float 完全一致——用四分之一存储换来了可接受的精度。"

## 6. 与硬件的关系（L7 延伸）
你的 PL 内核吃的就是这套 int8 数据：int8 权重 × int8 激活 → int32 累加 → Q16.16 定点 requant。**量化是"算法能被硬件加速"的前提**——这也是 AI 芯片设计的通用第一步。
