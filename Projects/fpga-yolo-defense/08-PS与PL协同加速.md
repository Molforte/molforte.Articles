# L7 PS+PL 协同与 5–6× 加速 · 组员共享版（最深一课）
> 用途：答辩最可能被连环追问的部分。核心三问：PS 怎么调 PL？为什么 5–6×？怎么更快？

## 1. 一次 PL 调用的完整机制（PS 让硬件算一层卷积）
```
① 检查：通道≤96 / 尺寸≤24×24 / K≤3 / 分辨率不变；超限→返回失败，调用方回退 CPU 卷积
② 软件数据 NHWC → 转 NCHW，写进 DDR 共享缓冲 in@0x10000000
③ 权重 OIHW + int32 bias 拷到 DDR（w@+0x20000、b@+0x60000）
④ Xil_DCacheFlushRange：冲刷 CPU 缓存（否则内核直读 DDR 看不到新数据）——cache 一致性！
⑤ 往 0x40000800 写 4 个 64 位内存地址寄存器（input/weight/bias/output）
⑥ 往 0x40000000 写标量参数（C_in/C_out/H/W/K/stride/pad/conv_type/scale，scale 转 Q16.16）
⑦ 写 ap_start → 内核启动：自己经 m_axi 读 DDR → BRAM → 计算 → 写回 DDR
⑧ 轮询 ap_done → Xil_DCacheInvalidateRange（失效缓存）→ 读回输出 → NCHW 转回 NHWC
```
**内核内部**：COPY 进 BRAM → 三重循环流水 II=1（每时钟一个输出像素）→ int8×int8→int64 累加（bias 起步）→ Q16.16 定点 requant `(acc×scale+32768)>>16` → 饱和 → COPY 回 DDR。内核**无 ReLU**（PS 补）——只做"纯卷积+量化"。
**K=5 为什么回退**：整层要进 BRAM，上限 ≤96ch×24×24，5×5 放不下（MAX_K=3）。

## 2. 数据通路的正确说法（⚠️ 团队必读，防翻车）
- **数据不走 AXI-Lite**：AXI-Lite 只是"下命令/写参数"的窄寄存器通道。
- **数据走共享 DDR**：PS 把数据写进 DDR，内核用自己的 **m_axi → S_AXI_HP0（高性能口）** 直读/直写 DDR。
- 最终版**没有 DMA**（9/1 优化去掉）：内核 m_axi 自搬，省掉 DMA 描述符与中断。若要进一步减 CPU 负担才考虑**加回 DMA** 或双缓冲——那是"更快"的路线，不是"当前用的方案"。
- 每层的搬运开销仍然真实存在：CPU 要做 NHWC↔NCHW 转置拷贝、逐层串行等 ap_done。

## 3. 为什么是 5–6× 不是 20×（诚实三归因，答辩缺一不可）
1. **容量限制**：只有 14 个 K=1 层能进硬件缓冲（≤96ch/24×24/K≤3）；占全网 **71% 计算量的 backbone** 还在 CPU。
2. **端到端稀释**：5–6× 是整帧加速；解码/NMS/未卸载层时间仍在，单层硬件加速远不止 5–6×【定性推断】，被总时间稀释。
3. **串行搬运开销**：每层搬数据 + 写寄存器 + 等 ap_done，逐层串行。
> 兜底句：*"加速比受容量（只有 14 层能上 PL，backbone 占 71% 仍在 CPU）和逐层串行搬运两个因素限制；5–6× 是端到端实测，单层加速本身远不止。"*

## 4. 升级路线（"如果重做/继续做"答案）
① 内核加 **tiling/行缓冲**，让 backbone 大层也能分块上 PL（理论还能快数倍）；② 加 **DMA 或双缓冲**，让 CPU 少参与搬运、流水化连续调用减少等待；③ 逐层流水/乒乓，隐藏搬运时间。诚实收尾："本次以 head 加速完成全链路验证，这些是后续优化方向。"

## 5. 速查与口径（背）
- 资源（no-ILA）：LUT ~5.4K/53K、BRAM 131/280、DSP 53/220；100MHz；WNS +0.297ns。
- `PL calls=22 errs=0` = 22 次接口调用 = **14 次真上 PL + 8 次 K=5 回退**；errs=0 指无超时错误。
- 地址：CTRL 0x40000000、control 0x40000800、共享 DDR 0x10000000 起 1MB。
- 5 翻车点：❌"22 层都加速" ❌"FPGA 主频高才快" ❌"全部卷积在 PL" ❌"纯计算加速" ❌"数据走 AXI-Lite / 用了 DMA"。

## 6. 答辩 30 秒表述（加速题）
> "PL 上放了一个 INT8 卷积内核，PS 通过写寄存器下命令、通过共享 DDR 递数据来调用它，整帧推理中 22 次调用、14 层真正在硬件上跑。同一张图从纯软件 15–20 秒降到 3.3 秒，端到端 5–6 倍，且结果与纯软件一致。加速受限是因为硬件缓冲容量只放得下 14 层小卷积，占七成算力的 backbone 还在 CPU，加上逐层串行搬运的开销。"
