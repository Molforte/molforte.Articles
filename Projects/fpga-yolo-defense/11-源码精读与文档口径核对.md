# 备课底稿 · 导师第一手精读笔记（已核对源码行号）

> 用途：L3–L7 讲课依据 + 交叉审计子代理简报。凡标 ✓ 均为本导师亲自 read 核对过。

## A. HLS 内核 `01_hls/conv2d_int8_axilite_fixed.cpp`（112 行）✓
- 硬限制：MAX_C=96、MAX_H=MAX_W=24、MAX_K=3 → 单层全量进 BRAM（MAX_IN=55296、MAX_WT=82944）。
- 接口：input/weight/bias/output 走 **m_axi gmem0**（指向 DDR）；C_in/C_out/H/W/K/stride/pad/conv_type/scale_fixed 走 **s_axilite CTRL**；`ap_ctrl_hs`（ap_start/ap_done/ap_idle）。
- 布局：输入输出 **NCHW**、权重 **OIHW**（DW 时 [co][ky][kx]）；conv_type=1 判定 DW。
- 计算：int64 acc 从 int32 bias 起累加；**定点 requant**：`scaled=(acc*scale_fixed+32768)>>16`（scale_fixed 为 Q16.16），再饱和裁剪 [-128,127]。**内核无 ReLU**（PS 侧补）。
- 结构：COPY_IN→COPY_W→COPY_B→计算(CO/ROW/COL 三重循环, PIPELINE II=1)→COPY_OUT，全部经本地 BRAM。
- 保留分辨率：Ho=(Hi+2p-k)/s+1，要求 h/w 不变（stride 恒 1 用于 1×1 head 卷积）。

## B. 驱动 `04_vitis_sw/fpga_conv.c`（141 行）✓
- 寄存器：`s_axi_CTRL @0x40000000`（AP_CTRL@0x00，标量参数 0x10–0x50）；`s_axi_control @0x40000800`（4 个 64-bit 地址寄存器低字@0x10/0x1c/0x28/0x34，高字+4）。⚠️ 文件头注释写 0x40010000 是**过期笔误**，代码与 README/FINAL_RESULT 均为 0x40000800——答辩别被旧注释带偏。
- DDR 共享缓冲（PS 可见低段 0x10000000，共 1MB）：in@+0x00000（≤55296B）、weight@+0x20000（≤82944B）、bias@+0x60000、out@+0x70000。
- 单次调用 8 步：①限检（Ci/Co>96、ih/iw>24、k>3 → -3；ih≠oh→-4）②NHWC→NCHW 搬运 ③权重+bias memcpy ④`Xil_DCacheFlushRange`（cache 一致性！）⑤写 4 地址 ⑥写参数+`scale_fixed=(int)(mult*65536+0.5)` ⑦写 ap_start → 轮询 ap_done（2 亿次超时）⑧`DCacheInvalidate` 后 NCHW→NHWC 拷回。
- 全局 `pl_call_count`/`pl_err_count` → main 打印 "PL calls=%d errs=%d"。
- ⚠️ 舍入差异点：HLS 定点 `>>16` 对负半值向 +∞ 舍，C 浮点 mult 是远离零舍——理论可能 ±1 LSB，实际未触发（可当"我知道这个细节"加分项）。

## C. 软件算子 `04_vitis_sw/nn.c`（114 行）✓
- `conv_nhwc_mult`：NHWC 输入；权重布局 [ky][kx][(dw?1:ic)][oc]（dw 时逐通道）；int32 累加 + int32 bias → `v=acc*mult` 浮点 → ±0.5 舍入 → 饱和 [-128,127] → 可选 ReLU。语义即"金标"。
- 其它算子：maxpool(3×3,stride2,pad1)、nearest upsample、concat2、shuffle_split（channel shuffle 拆两半）、requant_inplace、relu_buf。
- MAX_OC=336。nn.h 与 quantize.Int8Runner"完全同构"（注释自述）。

## D. 主程序与解码 `04_vitis_sw/main.c`（131 行）✓
- 6 类：person/fire/smoke/small_veh/large_veh/2whl。⚠️ 不是只有火烟——答辩说"灾后救援目标检测（6 类交通/灾情目标）"。
- 两尺度输出：22×22(stride16) + 11×11(stride32)；每格 21 通道 = 3 anchors×5 + 6 cls；anchors 两组各 3 个（如 (27.9,37.6)…）写死于 ANC 表。
- 解码：reg/obj/cls 各乘激活 scale（AS_out_* 常量≈1e-1~2.9e-1）；obj=`sigmoid(x)`；cls 过 softmax（先减 max 防溢出）；框中心 `cx=(sig*2-0.5+c)*stride`，宽高 `bw=(sig*2)^2*anchor`；score=obj×cls；CONF_TH=0.12、类内 NMS IoU=0.45；坐标钳到 0–352。det 结构体 {x1,y1,x2,y2,score,cls}。
- 主流程打印：BOOT → INF_START → run_inference(image_data, fin)（fin=22×22×21+11×11×21≈12.7KB int8）→ INF_DONE → decode → `D <n> <name> <x1> <y1> <x2> <y2> <score×1000> … OK` → PL 统计。
- 计时口径：UART 捕获 INF_START→INF_DONE=3.3s（PS-only 基线 15–20s 同口径）。

## F. 子代理简报已核对并入（SA2 量化链 + SA3 C 管线）✓✓

### SA3 补充（run_inference.c 结构）
- **run_inference.c 无"层表/层循环"**：gen_c.py 把 79 层**逐层展开为顺序语句**（每层调用带烘焙好的 mult 常量，如 r:140 mult=2.81e-3）。
- 特征缓冲全部为 **static int8 NHWC 全局数组**（最大 buf_x0[743424]=176×176×24），无 malloc；权重 static const → .rodata → DDR（lscript.ld: DDR ORIGIN 0x100000, LEN ~1GB 区段）。
- 输出拼装 pack_outputs：先 22×22 后 11×11，每格 21B。坐标直接落 352 空间，**无二次映射**。
- 22 处 fpga_conv2d_wrapper 调用全部位于 FPN 检测头（conv57-72）+ 6 个 out_reg/obj/cls_2/3；**backbone 全软件**。判定在 wrapper 内（通道≤96、h/w≤24、k≤3、保分辨率）：静态推导 **14 个 k=1 层真走 PL、8 个 k=5 层恒回退 SW** —— 与 README 的 14/8 吻合。
- 代码内**无计时逻辑**；"PS-only 15-20s / 3.3s"为 UART 外部计时口径（INF_START→INF_DONE）。
- 图片：image_data.h 单张 195.jpg，352×352×3 uint8，cv2 BGR、INTER_LINEAR、对称量化 /127。

### SA2 补充（量化公式，全部行号锚定）
- 权重：`ws=max|w|/127`（per-tensor 对称，零点 0，实际值域 [-127,127]）；`wq=clip(rint(w/ws),-128,127)`。
- BN 先融合进 conv：`std=√(var+1e-5); f=bn.w/std; fw=w·f; fb=-bn.mean·f+bn.bias`。
- bias int32：`bias_q=rint(fb/(ws·s_in))`，**先加进 int32 acc 再整体乘 mult**（不是 requant 后加）。
- 激活 scale：训练图 float 前向收集每层输出 maxabs → `act_scale=maxabs/127`；输入图 scale=1/127。
- requant：**浮点乘** `q=rint(acc·mult)`，`mult=s_in·ws/s_out` 每层独立，由 gen_c 烘焙进 C 代码。
- scales.json：w_scales/act_scales/bias_int32 三个字典 × **79 键**（79 个 conv，含 6 个输出头层）。
- 权重排布双份：`weights_all_int8.h`（804KB，sw 用，[oc,ic,kh,kw]→transpose→[kh,kw,ic,oc] 展平）与 `weights_oihw.h`（762KB，PL 用，OIHW）。
- 精度数字：float vs PyTorch 6 输出 max|diff|≤1.4e-5；INT8 vs float cos：obj 0.993 / cls 0.83-0.86 / reg 0.89-0.90。证据链：numpy↔C(x86) **fin 逐字节相等**；C(x86)↔ARM 板 UART 字符串一致（"D 1 fire …156 OK"）。
- 基线平台口径：Cortex-A9 单核 667MHz，15–20s/帧。
- 舍入细节：numpy np.rint 是 half-to-even，C 是 half-away-from-zero——理论仅恰在 0.5 处可差，实测逐字节一致（答辩加分细节）。
- 【未确认】标定图数：q 默认 32 张、文档记 512 张，scales.json 由哪次生成无记录。

### G. SA4 简报已核对并入（PL 集成与演进）✓

- **axilite.cpp（非 fixed）与 fixed.cpp 计算逐行相同**，仅 pragma 不同：前者四指针额外挂 s_axilite 且 m_axi 限 max_w_burst_length=16（"未固化版"），fixed 版去除 → 交付 IP 顶层为 `conv2d_int8_axilite_fixed`（02_ip_package RTL 实证）。⚠️ final.tcl 里 add_files 写的是 axilite.cpp，命名与交付 IP 错位【未确认，历史多次综合】。
- **最终版无 axi_dma**：内核自带 m_axi 从 DDR 搬 BRAM↔DDR（fpga_conv.c:13 流程注释）；老 stream 版才有 axi_dma_0 @0x40400000 + axis 中断（起步清单:14）。axis 32bit 打包/TLAST 是老版语义（起步清单§4.6），新版无此概念——两版叙事勿混。
- **calls=22 口径**（重要，答辩数据一致性）：`pl_call_count++` 在守卫检查**之前**（fpga_conv.c:82），故 22 次调用含 **8 次被 -3 拒绝的 K=5 尝试 + 14 次真上硬件**；`pl_err_count` 只在超时(-2)时 +1，-3/-4 不计 err。README "PL calls=22 errs=0" 应表述为"22 次硬件接口调用、0 次错误；其中 14 次真正在 PL 上执行，8 次 5×5 超内核上限自动回退 CPU"。
- **寄存器分址**：0x40000000 = 标量参数 + ap_start/done（RTL 实证 ap_ctrl 属 CTRL s_axi）；0x40000800 = 仅 4 个 gmem 64-bit 地址寄存器。⚠️ README 与 fpga_conv.c 头注都出现过把 start/地址混写或写 0x40010000 的过期表述——**以代码 + RTL 为准**。
- **演进叙事**（答辩"踩过什么坑"素材）：07-21 stream 内核源码就绪未综合 → 08-09 位流只有"单层固定权重"简化 IP（8 参、无 weight/bias 寄存器，不能换权重跑 79 层）→ 08-31 定路线 C（重综合可换权重内核 + head 上 PL）→ 定版：**去 stream+DMA 改 m_axi 直读 DDR、浮点 scale 换 Q16.16 定点、权重可逐层换**，时序收敛 WNS+0.837ns → bit-exact 5–6×。
- 部署脚本分工：vivado_deploy_*.tcl=下位流；xsct_deploy_axilite.tcl=老 TrackA 实验（tracka_app.elf）；xsct_deploy_maxi.tcl / run_elf.tcl=下位流(可选)+dow yolo_sw.elf+con；fpga_demo.py=完整演示（任意图 resize352→int8→写 DDR magic→串口监听→xsct dow→解析 "D n … OK"→画框）。⚠️ 脚本里 bit 路径指向旧绝对路径，现场以 README 的 no-ILA `design_1_wrapper_pl.bit` 为准。

### H. SA1 简报已核对并入（网络结构）✓

- 训练配置：classes=6、352×352、anchor_num=3、12 anchors（模型配置_disaster_local.data L13-17）；权重 disaster-80-epoch AP=0.6601@epoch80。
- 输入预处理：cv2 BGR + INTER_LINEAR → 352²，÷255→[0,1]；INT8 输入 `q=round(x·127)∈[0,127]`（decode_check.py L80）——不是 [-1,1]，答辩说"0–1 归一化 ×127"。
- 结构：first_conv 3×3/s2 3→24 + ReLU + MaxPool 3×3/s2/p1（注：接口规范里写 2×2 已过时）；stage2/3/4 = 4/8/4 个 block，输出 48/96/192 通道 @44²/22²/11²；仅每 stage 的 block0 是 s=2（带 proj 分支）。**图内无 SPP**【未确认】。
- ShuffleV2Block：s=1 块 = channel shuffle 奇偶拆半 → main(pw1×1→dw3×3→pw1×1) → concat；s=2 块 main/proj 各含 dw+pw。主干归属 ShuffleNetV2 仅见于注释，"ShuffleNetV2 主干"表述【未确认】（仓库名 YOLO-FastestV2 确凿）。
- LightFPN：conv56 1×1 192→72(S3@11²)；b4_3_out 最近邻 ×2 与 stage3 输出 96 concat → 288 → conv55 1×1 288→72(S2@22²)。
- Head：每尺度 cls/reg 两并行支各 4 conv（5×5DW→1×1→5×5DW→1×1，72ch）；末 1×1 输出 reg→12、obj→3、cls→6。输出两尺度 22²(s16)/11²(s32)，无 44 尺度。
- conv 总数 **79 = conv0..72(73 个) + 6 个 out_\***，与 scales.json 79 键互相印证 ✓。命名规律 backbone_{stage}_{块}_branch_{main|proj}_conv{N}；maxpool/upsample/concat/shuffle 不占编号（SCHEDULE 执行序）。
- 解码（decode_check.py L23-76）：每格 21 通道 = [reg12|obj3|cls6]，cls 三 anchor 共享；obj sigmoid 阈值 **0.30**（注：板上 main.c 用 0.12 为"过滤后候选"的更低阈值，两处口径不同——答辩以 main.c 实际为准）；NMS 类内 IoU=0.45；验收=框 IoU>0.5 且与 float 同公式比对。
- 答辩可引数字：**0.23M 参数 / INT8≈250KB / BRAM≈45%**（对照 YOLOv3-Tiny 8.7M/94%，项目核心理解.md）。
